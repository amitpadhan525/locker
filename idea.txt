===============================================================================
IDEAS & SPECIFICATIONS FOR AN ENCRYPTED DATA STORAGE & VAULT APPLICATION
===============================================================================

1. APP CONCEPTS & USE CASES
-------------------------------------------------------------------------------
* Concept A: Encrypted Local Virtual Drive / Vault (Cryptomator / VeraCrypt style)
  - Mounts encrypted folder structures as virtual drives (using FUSE on Linux/macOS, Dokany/WinFSP on Windows).
  - Files are encrypted individually (file-level encryption) to simplify cloud sync (Google Drive, Dropbox, Nextcloud).

* Concept B: Zero-Knowledge Encrypted Cloud Storage & Sync App
  - Desktop, mobile, and web app.
  - Client-side end-to-end encryption (E2EE) where data is encrypted before leaving the device.
  - Server sees only opaque encrypted blobs and has zero knowledge of master key or filenames.

* Concept C: Developer & CLI Secret Storage / Dotfile Vault (SOPS / age style)
  - Lightweight command-line utility for encrypting config files, secrets, environment variables, and databases.
  - Integration with YubiKey / FIDO2 security keys, SSH keys, and age identity keys.

* Concept D: Self-Destructing Ephemeral Data Sharing (Encrypted Link Sharing)
  - Web service allowing users to encrypt a file/text in the browser using WebCrypto API.
  - Encryption key is stored in the URL fragment (e.g., https://app.example/#key=...). Server never sees key.
  - Expiry parameters: Time-locked (e.g., 24 hours) or read-locked (deletes payload after 1 download).

* Concept E: Plausible Deniability Vault with Decoy Partitions
  - Supports multiple master passphrases for a single encrypted container.
  - Decoy passphrase unlocks dummy files; actual passphrase unlocks sensitive data.
  - Leaves no cryptographic signature proving the existence of hidden volumes.


2. CORE CRYPTOGRAPHY & ARCHITECTURE
-------------------------------------------------------------------------------
* Encryption Ciphers:
  - AES-256-GCM or XChaCha20-Poly1305 (Authenticated Encryption with Associated Data - AEAD).
  - Ensures both confidentiality and data integrity (detects tampering/bit-flips).

* Key Derivation & Stretching:
  - Argon2id (Winner of Password Hashing Competition) or PBKDF2 with 600,000+ iterations.
  - Protection against GPU/ASIC brute-force cracking attacks.

* Key Management:
  - Master Key derived from user passphrase + random salt.
  - Data Keys: Each file or data chunk is encrypted with a unique symmetric key, which is itself encrypted by the Master Key (Envelope Encryption).
  - Hardware Key Integration: Support unlocking via TPM 2.0, Apple Secure Enclave, Android Keystore, or FIDO2/YubiKey.

* Recovery Mechanism:
  - 24-word BIP-39 mnemonic seed phrase generated upon vault creation.
  - Optional Shamir's Secret Sharing (split recovery key into 3 parts, requiring any 2 to restore access).


3. KEY FEATURES & UX ENHANCEMENTS
-------------------------------------------------------------------------------
* Multi-Factor Authentication & Biometrics:
  - Touch ID, Face ID, Windows Hello, and Linux PAM/Fingerprint authentication for quick unlock.
  - FIDO2 / WebAuthn hardware token support.

* Auto-Lock & RAM Hygiene:
  - Secure memory allocation (using mlock/VirtualLock to prevent memory swapping to disk).
  - Automatic memory zeroization (memzero) of keys upon locking or idle timeout.
  - Auto-locks on screen lock, sleep, or after X minutes of inactivity.

* File Integrity & Audit Logging:
  - HMAC or AEAD tag verification before decrypting files.
  - Local immutable event audit log tracking access attempts, lock events, and failed password entries.

* Secure Shredding & Cleanup:
  - Multi-pass secure file deletion (DoD 5220.22-M or Gutmann method) when removing decrypted temporary files.


4. RECOMMENDED TECH STACK
-------------------------------------------------------------------------------
* Core Crypto Backend:
  - Rust (using `ring`, `libsodium-sys`, or `age` crates) for memory safety and zero-cost abstractions.
  - Alternatively: Go (using `golang.org/x/crypto`) or C/C++ (using `libsodium`).

* Desktop Interface:
  - Tauri + React/Vue (ultra-lightweight footprint, native Rust backend).
  - Qt / C++ or Flutter Desktop.

* Mobile Applications:
  - Swift / iOS Native & Kotlin / Android Native with unified C/Rust crypto engine via FFI.

* Web Client:
  - WebAssembly (Wasm) compiled from Rust/libsodium + WebCrypto API.
